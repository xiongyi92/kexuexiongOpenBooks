# 🧭 阅读路线图

按你的角色和目标，从下面的路线中选择一条开始。

## 路线 A：我想成为云原生 / 运维工程师

```
OpenVPN 企业实战指南 → 运维宝典 → 深入浅出 Kubernetes
```

| 阶段 | 书籍 | 说明 |
|------|------|------|
| 1️⃣ 网络与 VPN 基础 | [OpenVPN 企业实战指南](OpenVPN企业实战指南) | 篇幅短（46 页），快速掌握 PKI、隧道、路由等网络基本功 |
| 2️⃣ 运维全景 | [运维宝典](运维宝典) | 打通服务器、网络、数据库、中间件、云平台的完整知识面 |
| 3️⃣ 云原生进阶 | [深入浅出 Kubernetes](深入浅出-Kubernetes) | 42 章 + 12 个动手实验，跟着实验章（第 31–42 章）练一遍 |

> 三本书的呼应点：《运维宝典》第 12 章"云原生技术体系"是《深入浅出 Kubernetes》的预告片；《深入浅出 Kubernetes》第 21 章故障排查可对照《运维宝典》第 19 章应急响应阅读。

## 路线 B：我想做支付 / 金融科技架构师

```
银行会计学（程序员视角） → 移动支付架构设计
```

| 阶段 | 书籍 | 说明 |
|------|------|------|
| 1️⃣ 业务语言 | [银行会计学（程序员视角）](银行会计学-程序员视角) | 先用 30 分钟看懂借贷记账，再建立复式记账、对账、清算的心智模型 |
| 2️⃣ 架构实战 | [移动支付架构设计](移动支付架构设计) | 带着 DDD、事件驱动、分库分表、单元化、异地多活等主题，攻下 5 万 TPS 案例 |

> 呼应点：《移动支付架构设计》的"账户记账服务""清结算与对账"章节，正是《银行会计学》第 6–8、14–15 章的工程化落地。

## 路线 D：我想掌握 AI 智能体

```
Deep Agent 框架 → 企业 AI Agent 集成与私有化部署实战 →（结合自身方向回路线 A/B/C）
```

| 阶段 | 书籍 | 说明 |
|------|------|------|
| 1️⃣ 原理与安全 | [Deep Agent 框架](Deep-Agent框架) | 智能体原理、ReAct 与规划、沙盒隔离、Docker/K8s 部署与企业治理 |
| 2️⃣ 企业落地 | [企业 AI Agent 集成与私有化部署实战](企业AI_Agent实战指南) | 同样是智能体，但换到存量 Java 系统的现场：防腐层、vLLM、RAG、多租户、STRIDE 与成本治理 |

> 呼应点：前者的"沙盒隔离"是后者第 13 章多租户与第 17 章工具调用边界的技术前提；后者的第 2 章几乎逐条对应前者第 1–3 章，可对照读。部署章节（容器化、Kubernetes）可搭配 [深入浅出 Kubernetes](深入浅出-Kubernetes) 第 3、31 章阅读。

## 路线 E：我想做嵌入式 / 物联网开发

```
ESP32 开发实战快速入门 → BMS 电池管理系统
```

| 阶段 | 书籍 | 说明 |
|------|------|------|
| 1️⃣ 动手入门 | [ESP32 开发实战：快速入门](ESP32开发实战快速入门) | 148 页、30 章，五大部分层层递进；按附录 G 的 30 天路线图走一遍，能独立做出联网设备 |
| 2️⃣ 行业纵深 | [BMS 电池管理系统](BMS电池管理系统) | 同样的 MCU 与采样链路，但要求功能安全、CAN 通信、AUTOSAR 与量产认证——从"能做"到"能出厂" |

> 呼应点：《ESP32》第 7 章 ADC 采样、第 8 章定时器中断、第 17 章 FreeRTOS，对应《BMS》第 6 章的采样链路、任务调度与第 12 章的软件工程；前者是玩具级验证，后者是车规级约束。云端部分则可用 [深入浅出 Kubernetes](深入浅出-Kubernetes) 承接。

## 路线 F：我想给工程师的大脑补一点人文

```
在星空与道德律之间（书 + 60 页课件）
```

| 阶段 | 材料 | 说明 |
|------|------|------|
| 1️⃣ 先看课件 | `在星空与道德律之间_教学PPT.pptx` | 60 页、13 个单元，每章 4 页（时代冲突 → 问题现场 → 对照表 → 现代回响），两小时能过一遍主线 |
| 2️⃣ 再读书 | [在星空与道德律之间](在星空与道德律之间) | 247 页，导论 + 11 章 + 结语；每章附「想一想」与分类书目 |

> 为什么工程师该读：第 11 章的"语言转向"说"哲学的病，多半是语法造的"，与工程上的抽象、命名、接口设计其实是同一件事——把模糊的问题问清楚；而全书反复回到的"我该怎么活"，是任何技术路线图都不会替你回答的那一格。结语"AI 时代，哲学为什么更缺不得"可以直接接着路线 D 读。

## 横向关联速查

- 🐳 **容器化**：Kubernetes（第 3–9 章）↔ Deep Agent 框架（Docker/K8s 章节）↔ 运维宝典（第 12 章）
- 🔐 **安全**：OpenVPN（加密与认证）↔ 移动支付架构设计（安全架构、数据合规）↔ 运维宝典（第 21–22 章）
- 🧾 **记账**：银行会计学（会计引擎）↔ 移动支付架构设计（账户记账服务）↔ 两本财务书（核算体系）
- 🔌 **嵌入式**：ESP32（外设、RTOS、驱动）↔ BMS（采样链路、状态机、AUTOSAR、功能安全）
- ⚡ **可靠性**：BMS（可靠性工程、FMEA、质量体系）↔ 运维宝典（容量规划、应急响应、容灾）
- ☁️ **端到云**：ESP32（云端物联网平台）↔ BMS（云 BMS 与数据平台）↔ Kubernetes（服务端部署）↔ Deep Agent（数据智能决策）
- 🤖 **智能体两条腿**：Deep Agent 框架（原理与沙盒）↔ 企业 AI Agent 实战（Java 集成、vLLM、多租户、安全治理）↔ WorkBuddy 在财务中的应用（业务侧落地）
- 🧠 **提问与抽象**：在星空与道德律之间（如何提问、语言转向）↔ 各书的方法论章节（架构设计原则、选型对比、评估体系）——本质都是把模糊问题拆成可验证的问题
